你好，我希望你帮我开发一个完整的 AI 电商运营助手项目。

# 项目目标

开发一个基于多模态AI + 大语言模型 + AIGC技术的电商商品智能分析与内容生成系统。

用户上传一张商品图片后，系统自动理解商品信息、分析商品特点，并生成完整的电商运营方案：商品定位、用户画像、卖点分析、商品标题、详情页文案、短视频脚本等。

本项目用于求职作品集展示，核心目的不是做商业产品，而是证明：

- 能将多模态模型应用到真实业务场景
- 能用 LLM 解决真实电商问题
- 能设计 AI 工作流与统一模型接口
- 理解电商运营流程与平台规则
- 理解 AI 的能力边界（知道什么能推、什么需要用户输入）

# 设计原则（重要）

1. 演示优先：评委/HR 没有 API key，也没有耐心等 40 秒。必须内置 Mock 示例模式 + 分步进度反馈 + 结果缓存。
2. 不做超出模型能力的事：材质、价格、品牌、竞争优势等不可见属性，单张图片推不准，必须由用户输入提供，视觉模型只做"可见属性"推断。
3. 深度优于广度：第一版只做少量功能，做到无可挑剔，不做八个半成品。
4. 分析用原图，抠图只做展示：背景去除（CV 能力）与视觉分析（LLM 能力）是两条独立链路，不串联。

# 一、项目整体流程

用户上传商品图片（可选：商品名称 / 补充说明文本）

↓

图片预处理（校验、压缩、限流）

↓

两条链路并行：

  链路A（分析）：原图 → Vision LLM 分析 → 结构化商品信息（含"视觉推断 / 用户提供"标注）

  链路B（展示）：原图 → rembg/SAM 主体抠图 → 透明背景 PNG（仅用于报告展示）

↓

LLM 生成运营内容（标题 / 卖点 / 详情页 / 脚本，按平台分版）

↓

生成营销素材方案（AI 图片 Prompt）

↓

汇总为《AI电商商品运营报告》并前端展示

关键点：**分析链路始终使用原图，保留场景上下文**；抠图结果不进分析链路，只作为报告里的"商品主体识别"视觉展示。

# 二、产品功能设计

## 功能1：商品图片上传模块

网页界面，用户可：上传图片、查看、删除、重新上传。

- 支持格式：jpg / png / webp
- 文件校验：类型白名单 + 大小限制 + 文件名清洗
- 可选文本输入：商品名称、补充说明（用于提供材质/品牌等事实性信息）

## 功能2：商品主体提取模块（展示用）

使用 rembg 第一版实现，代码结构预留 SAM / U²-Net 替换接口。

- 输入：原图
- 输出：透明背景 PNG
- 用途：报告中的"商品主体识别"视觉展示，**不进入分析链路**

## 功能3：商品视觉理解模块（核心）

将**原图**（+ 可选文本输入）发送给多模态大模型。

- 模型：统一接口，支持 GPT-4o Vision / Claude Vision / Gemini Vision
- 输出：**JSON Schema 强约束的结构化输出**，不使用"请输出 JSON"这种脆弱解析

字段分两类：

- 视觉推断字段（由图片得出）：商品类别、外观特点、产品风格、使用场景
- 事实输入字段（由用户文本提供，图片无法可靠推断）：材质、品牌、价格、竞争优势

每个字段标注来源（visual / user），前端明示。示例：

```json
{
  "name": "智能保温杯",
  "category": "生活用品",
  "material": {"value": "304不锈钢", "source": "user"},
  "style": {"value": "商务简约", "source": "visual"},
  "user_group": ["白领", "学生"],
  "selling_points": ["便携", "保温", "高颜值"]
}
```

## 功能4：用户画像生成模块

根据商品分析结果 + 用户输入，让 LLM 生成目标用户画像卡：年龄、职业、消费能力、购买场景、购买动机、痛点。

## 功能5：商品运营内容生成模块（核心）

根据商品信息生成，**按平台分版**（这是体现电商运营能力的关键）：

1. **电商标题**：同一商品生成"淘宝版 / 京东版 / 小红书版"三版标题，遵循各平台规则（淘宝 60 字关键词堆叠、京东偏专业、小红书偏种草）
2. **五点卖点**：5 条卖点，每条含"卖点标题 + 解释"
3. **商品详情页**：完整结构（消费者痛点 → 产品解决方案 → 核心功能 → 使用场景 → 购买理由）
4. **短视频脚本**：抖音/小红书脚本（标题、前三秒钩子、分镜、旁白、产品展示、结尾转化）

## 功能6：AI 营销图片方案生成

第一版**只生成 AI 图片 Prompt**（场景化描述），不真实出图。未来可选接入 Stable Diffusion / Midjourney / 可灵 / 即梦。

## 功能7（可选/推迟）：运营建议生成

非必须。若要加，定位为"基于商品信息 + 平台规则知识库生成运营建议"，**不做数据分析 Agent**（无真实数据，做就是空壳）。

# 三、技术架构

## 前端

React + TypeScript（或 Vue3）。页面：首页上传、分析进度页、运营报告页。UI 简洁、有作品集展示效果。支持加载进度反馈（分步 loading）。

## 后端

Python FastAPI。负责：图片上传校验、图片处理、AI 模型调用（统一接口）、Prompt 管理、结构化输出、结果缓存、数据返回。进度用 SSE 或任务轮询。

## AI 模块（统一接口 + 结构化输出）

在统一接口层封装"输出 JSON Schema"，三个模型供应商共用同一套 schema 与重试/降级逻辑。

```
backend/app/
  vision/          # 多模态视觉理解（原图分析）
  llm/             # 文本生成（标题/卖点/详情/脚本）
  segmentation/    # 主体抠图（rembg，预留 SAM 接口）
  prompts/         # 所有 prompt 模板
  services/        # 业务编排（分析、生成、报告汇总）
```

# 五、Prompt 工程要求

- 所有 Prompt 单独保存为模板文件，不写死。
- **平台分版**：标题、卖点、文案按淘宝/京东/小红书分别建模板。
- Prompt 文件：

```
prompts/
  product_analysis.txt        # 视觉理解（含 JSON schema 说明）
  title_taobao.txt
  title_jd.txt
  title_xiaohongshu.txt
  selling_points.txt
  description.txt
  video_script.txt
  image_prompt.txt
  persona.txt
```

# 六、数据库（SQLite）

保存用户上传记录 + 结果缓存。字段：

- id
- image_path（或 image_hash 用于缓存命中）
- product_info（结构化 JSON）
- generated_content（生成结果 JSON）
- created_time

同图二次上传命中缓存，秒开结果。

# 七、演示与部署

- **Mock 示例模式**：内置 2-3 个示例商品（保温杯、咖啡杯、耳机），一键加载预生成结果，无 API key 也能完整走完所有页面。
- `.env` 管理 API key，`.env.example` 提供模板。
- README 写清部署，目标 `docker compose up` 一条命令跑起来。

# 八、最终展示效果

用户操作：上传商品图片（可选填名称/说明）→ 点击"AI 分析商品" → 分步进度展示 → 系统返回报告页：

商品识别（抠图展示）→ 商品分析（标注视觉/用户来源）→ 用户画像 → 三版标题 → 五点卖点 → 详情页文案 → 短视频脚本 → AI 营销图片 Prompt

最终生成一份完整《AI电商商品运营报告》，可导出 Markdown/PDF。

# 九、开发优先级（MVP）

## 第一阶段（必须完成）

- 图片上传 + 校验 + 进度反馈 + 结果缓存 + Mock 示例模式
- 原图视觉分析（结构化输出）+ 并行 rembg 抠图（仅展示）
- 三版标题生成 + 五点卖点 + 详情页文案
- 短视频脚本 + AI 营销图片 Prompt
- 报告页 + 导出

## 第二阶段（可选增强）

- 运营建议生成（基于规则知识库）
- 用户画像卡深化
- 真实 AIGC 出图（SD/即梦等，接第三方 API）

## 明确不做（避免空壳/过度承诺）

- 数据分析 Agent（无真实销售数据）
- 通用 RAG 知识库（无清晰语料，价值低）
- 虚假的"竞争优势/材质"自动推断（改为用户输入）
